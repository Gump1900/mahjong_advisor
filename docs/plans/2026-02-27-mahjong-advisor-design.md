# 麻将策略助手 - 设计文档

## 项目概述

### 目标
开发一个麻将AI助手，像麻将老手一样"读牌"，根据当前局面给出最优出牌建议。

### 核心功能
- **手牌分析**：计算向听数、进张牌
- **局势推断**：基于弃牌推算各张牌的概率分布
- **对手建模**：预测对手的牌型和听牌
- **决策输出**：3-5个候选出牌，附带各维度概率评估

### 技术方案
**LLM + 计算模块 混合架构**
- 计算模块：负责精确的概率计算和牌数统计
- LLM：负责读牌推理、解释原因、给出建议

## 规则定义

### 牌的构成（144张）

| 类型 | 张数 | 说明 |
|------|------|------|
| 万饼条 | 108张 | 普通牌，可以吃碰杠胡，各36张 |
| 东南西北 | 16张 | 东风是花牌，南西北是普通风牌 |
| 中发白 | 12张 | 花牌 |
| 春夏秋冬梅兰竹菊 | 8张 | 花牌 |
| **花牌总计** | 24张 | 东风(4) + 中发白(12) + 季节花(8) |

### 游戏规则

#### 基本规则
- **吃牌**：只能吃上家（left）的牌
- **碰牌**：三家都可以碰
- **胡牌**：四组一对，有番就能胡，有人胡了就结束

#### 花牌规则
- **不能打出**：抓到花牌可以选择杠或不杠
- **策略性杠牌**：可以留着花牌，等听牌时再杠
- **杠开**：听牌时杠花牌，换来的牌胡了 = 杠开 = 8花（上不封顶）

#### 计分（花数）
- 4个明刻 = 5花
- 4个暗刻 = 10花
- 杠开 = 8花
- （MVP阶段暂不实现计分，专注于出牌策略）

## 数据结构

### 牌的表示

```python
# 牌的花色
Suit = Literal["万", "饼", "条", "风", "三元", "季节"]

# 牌的值
# 万饼条: 1-9
# 风: "东", "南", "西", "北"
# 三元: "中", "发", "白"
# 季节: "春", "夏", "秋", "冬", "梅", "兰", "竹", "菊"

# 一张牌
@dataclass
class Tile:
    suit: Suit
    value: str | int
    is_flower: bool = False  # 是否是花牌（东风、中发白、季节花）
```

### 游戏状态

```python
# 明牌类型（吃、碰、明杠、暗杠）
MeldType = Literal["chi", "peng", "ming_gang", "an_gang"]

@dataclass
class Meld:
    type: MeldType
    tiles: List[Tile]

# 游戏状态
@dataclass
class GameState:
    my_hand: List[Tile]              # 我的手牌
    discards: Dict[str, List[Tile]]  # 各家弃牌
                                     # "left": 上家, "right": 下家, "opposite": 对家
    melds: Dict[str, List[Meld]]     # 各家明牌
    flowers_in_hand: List[Tile]      # 我手里的花牌（未杠）
    konged_flowers: List[Tile]       # 已杠的花牌
    current_turn: Literal["me", "left", "right", "opposite"]  # 当前谁摸牌
```

## 模块设计

### 1. 计算模块 (src/core/)

#### tiles.py - 牌的基础操作
- 牌的创建、比较、哈希
- 牌的字符串表示和解析
- 花牌判断

#### hand_analyzer.py - 手牌分析
- `calculate_shanten(hand: List[Tile]) -> int`：计算向听数
- `get_ukeire(hand: List[Tile]) -> List[Tile]`：获取进张牌
- `get_discard_candidates(hand: List[Tile]) -> List[Tile]`：获取可打牌候选
- `is_tenpai(hand: List[Tile]) -> bool`：是否听牌
- `get_waiting_tiles(hand: List[Tile]) -> List[Tile]`：听哪些牌

#### probability.py - 概率计算
- `count_remaining_tiles(state: GameState) -> Dict[Tile, int]`：剩余牌统计
- `calc_chi_probability(tile: Tile, state: GameState) -> float`：被吃概率
- `calc_peng_probability(tile: Tile, state: GameState) -> float`：被碰概率
- `calc_risk_probability(tile: Tile, state: GameState) -> float`：点炮概率
- `calc_win_probability(state: GameState) -> float`：自摸概率

### 2. LLM 推理模块 (src/llm/)

#### advisor.py - LLM 顾问
- 构建包含局面信息和计算结果的 prompt
- 调用 LLM API 获取分析建议
- 解析 LLM 输出为结构化结果

### 3. 主程序 (src/main.py)

- 用户输入处理
- 调用计算模块获取概率数据
- 调用 LLM 获取建议
- 格式化输出结果

## LLM Prompt 结构

```
你是一位麻将大师，请根据以下局面给出出牌建议。

【规则】
- 144张牌：万饼条各36张 + 风牌16张 + 中发白12张 + 季节花8张
- 花牌（东风、中发白、春夏秋冬梅兰竹菊）可留着杠开，不能打出
- 吃只能上家（left），碰三家都可以
- 有番就能胡

【当前局面】
我的手牌：[三万, 四万, 五万, 七条, 八条, ...]
我的花牌：[春, 中]（未杠）

上家（left）弃牌：[...]
上家明牌：[...]

下家（right）弃牌：[...]
下家明牌：[...]

对家（opposite）弃牌：[...]
对家明牌：[...]

当前剩余牌数：XX张

【计算结果】
向听数：X
进张牌：...（剩余X张）
候选出牌及概率：
- 打X万：被吃概率X%，被碰概率X%
- ...

请分析：
1. 推断各对手可能在做什么牌型
2. 评估每个候选的风险和收益
3. 综合花牌策略（是否应该杠花）
4. 给出最终推荐（3-5个选项）及理由
```

## 输出格式示例

```
【推荐】打 五万

【候选列表】
1. 五万 ⭐推荐
   - 向听数：2→1（大幅改善）
   - 被吃概率：15%（上家可能在等边张）
   - 点炮风险：低
   - 理由：保留三四六万的进张，打掉孤张五万

2. 七条
   - 向听数：不变
   - 被吃概率：30%（下家可能吃边张听牌）
   - 点炮风险：中
   - 理由：孤张，但下家可能在等

3. 北风
   - 向听数：不变
   - 被吃碰概率：0%
   - 点炮风险：低
   - 理由：安全牌，但不会改善手牌

【对手分析】
- 上家（left）：弃了大量万子，可能在清一色条子
- 下家（right）：碰了两张发财，可能在对对胡
- 对家（opposite）：弃牌杂乱，可能还在凑牌

【花牌建议】
- 当前有一张「春」未杠，建议等到听牌时再杠，追求杠开
```
