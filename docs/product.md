# 产品

做一个网页与微信小程序共用后端的四人太湖麻将产品，提供机器人陪打、军师与复盘。大厅、房间、牌桌、结算采用玩家熟悉的麻将交互；太湖玩法和军师是特色。流程可参考欢乐麻将，美术、品牌、音效使用自制或有授权素材。

## 对局组合

| 真人 | 机器人 | 用途 |
| --- | --- | --- |
| 4 | 0 | 真人同桌 |
| 3 | 1 | 缺一人补齐 |
| 2 | 2 | 双人陪打 |
| 1 | 3 | 单人练习 |
| 0 | 4 | 机器人观战、对抗和数据采集 |

已实现访客开发版的网页／原生小程序同房间对局，不要求共享全部界面代码；手机真机与正式上线仍需验收。无登录的访客体验可先实现；正式身份认证、邀请权限和断线托管逐步完善。

## 主流程

入口 → 访客昵称 → 创建／加入房间 → 入座与补齐机器人 → 真人准备 → 房主明确开局 → 对局 → 结算 → 回房准备下一局。

打开页面或GET请求不得自动建局、发牌或触发付费调用。只有明确开局动作创建对局；重复开始不应产生第二局。下一局重新准备，不自动发牌。

## 六个模块

规则与对局引擎负责裁判；房间与联机负责参与和同步；策略负责打法；客户端负责呈现；军师与复盘负责建议和回看；实验室负责验证。详细边界见[架构](architecture.md)，规则见[规则](rules.md)，交互见[原型规范](../prototype/design.md)。

## 当前能力与目标的区别

已有网页试打、机器人与交互原型；共享服务已实现1～4位访客、机器人补位、两端同桌、私有手牌、重复／过期动作校验、结算后重新准备及活动局持久化恢复。已验证两个独立网页身份，以及微信开发者工具原生客户端与网页端协议的同桌双向出牌；真实微信手机、正式登录、邀请分享、超时托管和发布尚未验收。机器人与军师仍需持续评测，不宣称已经达到老手水平。

军师只使用当前座位可见信息，不能透露其他人的暗牌和未来牌墙。建议失败不影响出牌。多人桌是否开放军师、对谁开放、如何展示权限，正式邀请真人前确定。

## 首版范围与验收

首版先确保内部一真人三机器人从大厅打一局并回房，再完成多真人真实连接。验证准备、权限、重复提交、过期动作、断线与重连、正常结算和中止的区别。超时自动托管、真人接管机器人、转让房主、回收期限和观战权限仍待明确。

四机器人自战是评测基础设施，重复对局不会自动提升策略；模型或权重升级需离线验证。排行、赛事、商业化和复杂社交不进入首版必要范围。执行顺序统一见[路线图](roadmap.md)。
