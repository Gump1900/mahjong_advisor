# Web UI 重设计（v2）——设计文档

> 日期：2026-08-17
>
> 状态：已经用户逐节确认（方案 A + 三节设计），待用户审阅本文档
>
> 背景：Web UI v1 被"打回重做"。根因：交互是"模式表单"（选模式→弹牌库选牌），起手
> 手牌用文本框输入，摸的牌直接混进手牌，对手信息被动、无牌桌感，分析在侧栏与手牌
> 脱节，且我的碰/吃/胡需要手动声明。经头脑风暴确认四项核心需求：独立摸牌位、我的
> 鸣牌自动检测提示、分析标注在牌上、牌桌视角布局。

---

## 1. 目标与非目标

**目标**

1. 交互像"点着打牌"，不是填表：开局点选起手牌、点摸牌位声明摸牌、点任意牌打出。
2. 对手打出一张牌后，系统自动提示我能碰/吃/胡，我只点按钮或点"过"。
3. 引擎分析直接标注在手牌上（打出后向听/进张徽标 + 风险色环，推荐排序高亮），
   右栏保留详表（风险百分比、杠开机会、AI 建议）。
4. 牌桌视角：三家横排在上方（弃牌河 + 明牌 + 内嵌动作按钮），我在下方。
5. 胡牌后一键算花（选胡法 → 花数明细）。

**非目标**

- 不改引擎的向听/计分/风险算法与 CLI 会话模式；
- 不引入前端框架与构建链（仍是单文件 HTML/JS + 标准库后端）；
- 不做对手手牌模拟（只记录可见信息）；
- 不做移动端专门适配（桌面优先，窄屏可退化为单列）。

## 2. 布局

```text
┌─────────────────────────────────────────────────────┐
│ 上家●(内嵌[打][碰][吃][杠])   对家(…)   下家(…)        │
 │  各家：弃牌河（按打出顺序）+ 明牌 + 已打出张数           │
├──────────────────────────────┬──────────────────────┤
│ 我的花牌区（每张带小[杠]按钮） │ 状态行：听牌！胡：…/向听… │
│ 我的明牌区                    │ 候选详表（进张速度+风险%）│
│ ────────────────────         │ 杠牌/杠开机会            │
│ [13张手牌·点击打出] [◌摸牌位]  │ [问LLM] + 建议输出       │
│ ────────────────────         │ [撤销] [新对局]          │
│ 我的弃牌河                    │                        │
└──────────────────────────────┴──────────────────────┘
```

- 摸牌位是手牌右侧的独立格子：空时显示"摸牌"提示，有牌时高亮显示刚摸的那张；
- 手牌按花色排序显示；每张手牌上方有分析徽标（见 §4）。

## 3. 交互流（按打牌节奏）

1. **开局**：全屏牌库点选起手 13 张。牌库每张牌显示剩余张数（144 − 已见），
   选满 4 张自动禁用；花牌单独一区（选"起手花"，非结构手牌）；[开始对局]。
2. **我摸牌**：点摸牌位 → 弹牌库 → 点摸到的那张 → 后端 `摸 X`，前端把该张标记为
   摸牌位牌（手牌区仍显示 13 张）→ 分析刷新。
3. **我打牌**：点手牌或摸牌位任意一张 → 后端 `打 X` → 进我的弃牌河；打手牌时
   摸牌位那张并入排序后的手牌。
4. **对手打牌**：点那家 [打] → 牌库选牌 → 进其河；随后前端调 `/api/legal`，
   若我能碰/吃/胡这张，手牌上方浮现 `[碰] [吃 …] [胡！] [过]`。
   - 吃按钮直接列出可行组合（如"吃 4饼6饼"），一键完成；
   - [过] 收起提示；做过其它操作视为默认过；同一张牌不再重复提示。
5. **对手碰/吃/杠**：点那家面板对应按钮选牌（碰/杠 1 张、吃 3 张）；
   源牌自动从相应河移入明牌（后端记账，防重复扣减）。
6. **我的杠（自动浮现）**：手里 4 张同款 → 该组上方浮 [暗杠]；碰过又摸回第 4 张 →
   浮 [加杠]；花牌区每张带小 [杠]；听牌时右栏提示杠开时机（8 花起上不封顶）。
7. **胡牌**：状态行显示"已胡"；[算花] 弹窗选胡法（自摸/放炮/杠开）→
   `POST /api/score` → 显示总花与 breakdown 明细。

## 4. 分析标注（牌上）与右栏

- 每张手牌（含摸牌位牌）上方徽标：`向听/进张`（打出后的 discard_speed）；
  牌边框风险色环：安全=绿、中=黄、危险=红（discard_risk 标签）；
- 推荐排序：候选表第一名的牌加"推荐"角标并在牌上高亮；
- 右栏：状态行（向听/听牌/已胡 + 所胡牌 + 全桌剩余）、候选详表
  （进张种数/张数、被吃/被碰/点炮百分比条）、杠牌/杠开机会、[问 LLM] 按钮
  （无 key 失败时折叠展示 Prompt 预览）、[撤销] [新对局]。

## 5. 引擎与接口新增

**`src/core/hand_analyzer.py` 新增纯函数（配单测）**

```python
can_peng(hand, tile) -> bool
    # 手里有 >= 2 张同款
can_chi(hand, tile) -> list[list[Tile]]
    # 返回全部可行吃法（该牌作为被打出的那张），含边张与嵌张：
    # 如 tile=3万 且手里有 1,2 万 / 2,4 万 / 4,5 万
    # -> [[1万, 2万], [2万, 4万], [4万, 5万]]
    # 纯手牌判断，"只有上家能吃"由调用方控制
can_ron(hand, tile, fuuro=0) -> bool
    # calculate_shanten(hand + [tile], fuuro) == -1
```

**`src/web.py` 新增路由**

- `POST /api/legal` `{player, tile}` → `{"peng": bool, "chi": [[..], ..], "ron": bool}`；
  `chi` 仅当 `player == "left"` 时计算，否则恒空；
- `POST /api/score` `{win_method}` → 从当前 GameState 自动取暗牌/明牌/花牌，
  返回 `{"hua": int, "flowers": int, "breakdown": [..]}`。

## 6. 状态归属

| 状态 | 归属 | 说明 |
|---|---|---|
| 手牌/各家河与明牌/花牌/明牌杠 | 后端 GameState | 每次事件后随 `/api/state` 返回 |
| 摸牌位（刚摸的那张） | 前端 | 后端 `摸 X` 后手牌为 14 张；前端记住哪张是摸的，渲染时抽出放摸牌位；撤销后置空 |
| 出牌候选/风险/杠开机会 | 后端 analyze | 随 `/api/state` 返回 |
| 我的可碰/吃/胡 | 后端 `/api/legal` | 依据"最新被打出的那张"实时计算 |
| 已"过"的提示 | 前端 | 记住已处理的那张牌，不重复弹 |

## 7. 边界与防错

| 场景 | 处理 |
|---|---|
| 牌库点选超量 | 牌库每张显示剩余张数，选满禁用 |
| 打出手里没有的牌 | UI 只渲染手牌按钮；后端校验兜底 → toast |
| 碰/吃/杠找不到源牌 | 后端记账校验报错 → toast，局面不变 |
| 输错任何一步 | [撤销] 逐步回退（后端快照栈），摸牌位随撤销清空 |
| 手牌张数异常 | 14 张才允许打；13 张时点手牌给"先摸牌"提示 |
| 提示浮层与手动操作冲突 | 提示不阻塞任何输入；其它操作默认视为"过" |
