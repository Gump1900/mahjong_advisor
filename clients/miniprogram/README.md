# 手机试打与原生小程序

本目录是运行客户端，设计稿仍在 [prototype/miniprogram](../../prototype/miniprogram/index.html)。当前范围：访客好友房支持1～4位真人同桌、机器人补位；单人适配测试继续保留。共用真实裁判、随机完整牌局、吃碰杠胡、多选／全选换花与留花、听牌、互锁和结算。军师暂停，正式微信登录、邀请分享与真机验收尚未完成。

## 立即试打

在项目根目录启动：

```sh
python3 -m src.mobile.server --port 8773
```

打开 <http://127.0.0.1:8773/>，填写昵称后“开好友桌”或输入6位房号“加入房间”。双方准备，房主补齐机器人后明确开始。原生小程序在“连接设置”填写相同服务地址即可加入同一桌，各控自己的座位。共享桌没有客户端暂停／逐步，机器人由服务端推进。旧8766／8767调试桌继续独立；单人适配测试仍点“准备并开始”，不与好友房共享控制权。默认使用现有EV机器人（8次采样、零LLM费用）；快速调试可加 `--bot heuristic`。这是一台本机适配测试服务，不是正式联机服务器。

提供随机、留花换花、吃、碰、明杠、暗杠、听牌、自摸八种开桌场景；场景通过完整144张牌墙布置并由真实引擎执行，不使用假动作或样例分数。仅在新建桌时生效。原生首页也可选择测试场景。

模拟器支持844×390、740×360、932×430、915×412，入口自动使用对应竖屏尺寸；旋转、安全区、纯净预览、暂停／逐步、换花与留花、刷新后继续。点击手牌选中，再次点击打出；响应按“过、吃、碰、杠、胡”排列。只有合法动作才会出现；单独的“过”由裁判自动轮转。三位对手的暗牌统一尺寸，不从服务获得真实暗手。

可用 `/?seed=42` 复现测试局；只有首次创建测试桌使用种子，继续已有桌不重新发牌。平时省略种子，使用系统随机源。此开发参数不代表正式联机允许用户控制随机性。

## 导入微信开发者工具

1. 启动上述8773统一服务。
2. 在微信开发者工具中导入本目录 `clients/miniprogram`，编译类型选“小程序”。`project.config.json` 默认使用测试号配置；工具要求时使用自己的测试号／AppID。
3. 在工具的“本地设置”中勾选“不校验合法域名、web-view（业务域名）、TLS版本以及HTTPS证书”。仅限本机开发。服务地址在 `shared/config.js`。
4. 编译首页，开好友桌或加入网页显示的房间号；单人场景也可点击“准备并开始”。大厅为竖屏，牌桌使用页面级 `pageOrientation: landscape`。切换机型检查胶囊、安全区、横屏和触摸。

已在本机安装微信开发者工具 **2.02.2609250 Stable（Apple Silicon）**，以游客模式实际编译运行原生WXML工程，验证了：入口、服务地址检查与保存、横屏牌桌、留花／单张换花、双击出牌、机器人轮转、退出返回，以及真实自摸场景的结算（+18、其余三家各−6）。工具中的系统窗口API在横屏下仍可能返回竖屏尺寸，因此牌桌通过原生SelectorQuery测量实际容器，并在页面Ready／Resize时重新适配。游客模式下的登录／平台API返回不是正式微信验收结果。

跨端联调入口已切换到8773。已验证两个独立网页身份同桌、准备、出牌同步与刷新恢复；也验证微信开发者工具的原生客户端加入网页协议创建的房间、接收网页动作并打出自己的牌。双方game_id一致，暗手按各自座位脱敏；使用旧凭证在服务实际停止并重启后，房间、版本与各自手牌保持一致。这里的微信端仍是开发者工具，未代替手机真机验收。

同一浏览器资料中的网页标签共享访客身份；测试不同真人请用不同资料／无痕环境，或网页＋小程序。刷新／关闭页面不等于离桌；本地访客凭证是恢复座位的依据，不要清除它来测试重连。

### 同一Wi-Fi真机开发连接

真机的127.0.0.1是手机自身，不能填写开发电脑的本机地址。已补上显式开启的局域网调试模式，默认服务仍只监听本机。以下地址请换成电脑当前的局域网IPv4：

```sh
python3 -m src.mobile.server --host 0.0.0.0 --allow-host 192.168.1.8 --port 8772
```

启动后将服务地址与随机开发配对码写入忽略目录 `var/mobile-pairing.json`（文件权限600）。在小程序“连接设置”填入这两个值；配对检查覆盖健康检查、开桌和全部对局接口。不带配对码的请求不能创建测试桌或获取牌局。只允许指定的Host，且继续拒绝跨站操作。重复启动默认复用配对码；不要提交或共享此私有文件。

这是为后续真机调试准备的连接能力，**本轮没有连接真实手机**。微信开发者工具游客模式不能扫码预览／上传；需要用自己的微信开发者账号与小程序AppID导入工程，再按微信真机调试的网络限制配置。正式发布仍需合法域名、HTTPS、正式身份与并发／异常验收，不可将本机配对服务当作正式联机服务器。

## 文件归属

```text
clients/miniprogram/
├── app.* / project.config.json     原生工程入口
├── pages/home/                     竖屏入口与准备开局
├── pages/table/                    横屏牌桌、动作选择、结算
├── pages/room/                     好友房、座位、准备、补位与开局
├── pages/settings/                 开发连接设置与健康检查
├── shared/model.js                 座位观察→展示模型；两端共用
├── shared/controller.js            点选、提交、轮转、暂停、恢复；两端共用
├── shared/audio.js                 事件语音、播放队列、静音与恢复；两端共用
├── shared/mobile.wxss              两端共用牌桌样式
├── shared/layout.js                原生容器尺寸与安全区计算
├── shared/connection.js            地址、配对、原生HTTP与健康检查
├── shared/config.js                默认原生请求地址
├── assets/tiles/                   微信可直接加载的本地PNG
├── assets/audio/                   本地报牌、动作、结算语音与牌声
└── simulator/                      浏览器设备画框与DOM适配器
src/mobile/server.py                两端共用HTTP适配与独立练习桌
src/rooms/network.py                共享房间、座位授权、冻结窗口、服务端机器人、存档
```

不在客户端重写规则。共享房间复用 `RoomService`、`simulation.engine/observation`；房间协调器负责座位授权、冻结响应窗口与服务端机器人。单人测试继续复用 `DesktopTable`。客户端提交当前窗口版本、合法动作ID和唯一请求编号，不控制其他座位或裁判。军师关闭；不向客户端暴露种子、牌墙或他家暗手。终局后可以得到公开摊牌信息。

“换花”和“留花”为独立按钮：换花打开具体牌的选择，留花保留手牌并标记当前选择，继续自行出牌；不会提交虚构的留花规则动作。花牌面板支持逐张勾选、全选／取消全选和一次确认换N张；同名花牌按实际张数分别选择，一次请求按单张规则依次换回，四张同名花牌不会被暗中当成暗杠；新补到花牌不会递归换掉，四张相同花牌的暗杠走单独“杠”动作。暗杠桌上显示牌背；明杠与加杠统一呈现。关闭客户端不算离桌；后台／隐藏页面停止拉取，回来继续。共享房间的机器人继续由服务端调度，轮到离线真人时等待，不默认接管。共享房间及待响应动作保存到 `runs/shared-rooms/state.json`（权限600、原子替换、进程文件锁），进程重启后旧凭证可恢复；主动离桌会中止当前局，房主离开由剩余第一位真人接任。结束或换局前的私有牌谱保存在同目录archives。单人适配测试仍为内存桌、牌谱位于 `runs/mobile/`，不承诺其重启恢复。若请求断开，客户端暂停并重新拉取当前版本，不自动重发出牌请求。

## 验证

牌桌默认开启声音，顶部“声音开／关”保存本机偏好；原生小程序跟随系统音量与静音模式。出牌播报牌名，吃、碰、杠、胡、换花播报动作，终局播报自己的输赢分数。摸牌只播放牌声，暗杠不报牌名。首次进入、刷新和后台恢复不重播历史动作；批量换花只播一次。音频使用本地资源，无需在线语音服务；执行 `python3 -m scripts.build_mobile_audio` 可重建，需 macOS 系统语音与 ffmpeg。

```sh
python3 -m pytest -q tests/test_shared_rooms.py tests/test_shared_http.py tests/test_rooms.py tests/test_mobile_simulator.py
node --test tests/mobile_audio.test.cjs tests/mobile_client.test.cjs tests/mobile_native.test.cjs
```

覆盖不同测试桌隔离、脱敏、非法／过期动作不执行、跨站拦截、静态资源边界、完整一局计分、继续和结束。浏览器适配检查包括入口到真实牌局、花牌选择、双击打牌、四种尺寸、旋转、安全区、刷新继续。

补充检查覆盖连接地址校验、配对头、错误服务识别、网络中断保留牌局、后台停止后不再轮转，以及横屏事件／页面实测尺寸与旧竖屏安全区冲突的处理。

共享房间测试覆盖1／2／3／4位真人完整对局与计分一致、房主权限、座位隔离、多玩家同窗响应、重复请求、待响应恢复、离线与主动离桌的区别、重启凭证恢复和存档独占。同步方式为约700ms只读轮询，尚未引入WebSocket或正式微信身份。
