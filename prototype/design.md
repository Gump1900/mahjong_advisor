# 产品交互与原型规范

唯一原型规范。原型入口见[index.html](index.html)，维护方法见[README](README.md)；玩法只以[规则](../docs/rules.md)为准。Block展示、Flow编排、App组装，右侧注释与场景数据一起维护。

## 产品流程与状态

大厅 → 创建／加入访客房间 → 入座／机器人补齐 → 真人准备 → 房主明确开始 → 牌桌 → 结算 → 回房准备下一局。打开页面不建局、不发牌；下一局明确开始。

| 页面 | 正常 | 空态／失败 |
| --- | --- | --- |
| 大厅 | 昵称、创建、加入、继续活动房间 | 无房间不显示继续，不自动建房 |
| 加入 | 6位房号、提交、重试、返回 | 不存在／满员／已开局分别解释，错误不清空输入 |
| 房间 | 四座位、真人／机器人、房主与准备状态 | 缺座／未准备不能开始；普通成员不能替房主操作 |
| 牌桌 | 本人操作、三家动作、军师 | 未加载用—，保留最后确认状态并阻止过期提交 |
| 结算 | 各家净得失、逐笔付款、分项、局号 | 黄庄是真实零结算；结果未知不能冒充0 |

房主只向空座补机器人，不顶替真人；机器人自动准备，每位真人控制自己的准备。成员／机器人配置变化重置真人准备；重复开始不产生第二局。房主离开等待房间目前采用确认解散建议，转让／期限政策未定。

原型加入样例286319；404404不存在、999999已满、888888已开局。邀请仅展示本地信息，不实际发送、不提供跨设备连接。正式房号／邀请／身份由服务端授权，不以昵称控制座位。

## 微信小程序原型

入口：[手机小程序](miniprogram/index.html)。独立手机布局仍使用Block→Flow→App：`blocks/mobile.js`复用既有`Blocks.tile/meld`，`flows/miniprogram.js`负责本地状态与权限，`app/miniprogram.js`装配页面和评审注释。小程序画板样式在`shared/miniprogram.css`，不覆盖桌面样式。

| 页面 | 逻辑画板 | 主要决策 |
| --- | --- | --- |
| 首页／加入／房间 | 390×844竖屏 | 不强制登录；建房与加入分开；准备与开局分开 |
| 进入牌桌 | 竖屏过渡 | 说明横屏再进入；这里切画板，不调用设备方向API |
| 牌桌 | 844×390横屏 | 预留胶囊与安全边距；本人手牌32×44，三家暗牌统一14×20；本人牌更大便于选择 |
| 结算 | 390×844竖屏 | 自己得失与四家分数优先，付款与牌型明细展开查看 |

这是横竖屏切换的设计提案，尚未在真实微信容器验证。顶部状态栏、胶囊、底部手势条是外壳示意，不把原生胶囊功能做成假产品按钮。好友邀请只展示房号，不发送消息。

本版军师模块不展示。继承同排副露、浅绿／淡蓝牌背、左侧常驻待牌、未听牌留空、合法动作排序、第三口仅锁定后提示。手机场景覆盖开局、选牌、等候、吃牌选择／提交／过期、碰、明杠／暗杠／加杠、批量换花与补到新花、听牌、过胡、互锁、自摸／杠开／多响／黄庄结算、断线／暂离／恢复及四杠满载。

原型保存本标签页的本地流程状态。单人退出中止；多人暂离保留本地继续入口；重连示例保留原手牌，不重发牌。正常走主流程时出牌后会模拟短暂等待和下一次摸牌；评审链接加`?review=1`可停住检查。场景跳转和样例分数不是完整合法牌谱或真实联网对局。

## 画板、座位与组件

评审工具左场景、中画板、右注释，编号可定位；标记不进入正式产品。画板1100×820等比缩放，四家同类牌尺寸一致。本人在下、下家右、对家上、上家左，整体牌列旋转，不单独缩小侧家。

| 对象 | 逻辑尺寸／布局 |
| --- | --- |
| 四家手牌 | 38×54；间距3；新摸牌间距14 |
| 本人选牌 | 上抬12；再点同牌出牌，换选不提交 |
| 副露 | 32×45；完整组显示，横牌不压扁 |
| 牌河 | 25×35；单家最多25张，9＋9＋7三行 |
| 单花 | 25×35；上限24张，侧家可12＋12 |

牌背默认浅绿，可切淡蓝、玉白；浅绿／淡蓝表示两副整牌，不在同一手交替。没有缺一门或禁打某门，非本人阶段只是不能提交，手牌不灰化。

## 同排牌列、来源与容量

四家共用“副露＋剩余手牌”一排，前方只有花牌和弃牌。无副露摸后14张；每多一组，剩余暗手基准少3张：11、8、5、2。四吃／碰12张＋2手牌是14实体；四杠16张＋2手牌最多18实体，不能假定所有状态都是14。

吃只能来自上家，实际吃入的牌移到最左横放。碰／明杠横牌位置表示来源：上家左、对家中、下家右；只有一张横牌。明杠、加杠显示相同四张明牌，加杠继承原碰来源且不新增口数，不叠牌。暗杠对他人只见四背，类别也保密。

未换出的花仍占手牌位。单花最多中发白东16张加季节花8张，共24；四花一次暗杠进入副露，不再重复放单花区。四家分别检验16杠＋2手牌＋24单花＋25弃牌组合；这是区域压力样例，不代表四家同时可持这些实体牌。

来源从实际成功事件恢复，弃牌被吃碰后离开牌河；不能显示两份实体牌。花、牌河的锚点不因副露数量改变，名字和来源字不互相遮挡。

## 高频操作与听牌

响应固定“过、吃、碰、杠、胡”顺序，仅显示合法项，整体居中。没有吃碰杠胡就没有“过”或空黑框。暗杠／加杠归杠，自摸／杠开归胡，具体类型在流程和结果说明；换花是另行决策。

本人听牌提示常驻手牌区最左侧，不放视口顶端，不覆盖对家。别家摸打／播放动作时不消失、不闪烁、不重播出现动画；信息不变不重建牌面，多面听滚动位置保留。

每种待牌显示牌面、未见张数、可接炮／仅自摸；原因区分过胡、资格和互锁。未见包含他家暗牌，非真实墙内活张；0弱化保留，未知用—。选牌预览写“打某张后听”，不说成已经听；换选即更新。未听牌整个区域留空，不显示“尚未听牌”、空卡或边框；留花未处理、终局后清除。

点一下选牌，再点同牌提交。吃牌组合与换花批次未选时不能确认；取消不改局面。阶段区分选中、待确认、提交中、已接受、仲裁完成、拒绝／过期。点击成功不等于吃碰已经赢得仲裁，被胡拦截不记口。

## 三口提示

从裁判有向成功事件累计。第三口提交前说明将永久禁接炮及直接关系支付×3，取消／被拦不记；成功后只在互锁双方显示标记。未锁定不展示口数进度或徽标。点击已锁定关系可查来源和动作；本人限制显示仅自摸／杠开，正常过圈不解除。具体计分不在原型另算。

## 军师

默认推荐动作、一句理由、三家各一句判断。证据不足只写“无法推断”。详细概率、候选、依据、旧建议和设置默认折叠。建议缺失／失败写“建议暂不可用”，不中断对局。既往建议明确为历史，不能覆盖当前状态或把过期结果当当前指令。

## 离开、恢复与结算

| 情况 | 行为 |
| --- | --- |
| 单人陪打主动离开 | 确认中止，不伪造正常胡牌结算 |
| 多人暂离／返回大厅 | 保留房间与座位，提供继续入口；不擅自托管或结束别人的局 |
| 等待房间离开 | 普通成员释放座位；房主确认解散是当前建议 |
| 断线 | 遮罩阻止提交；恢复同房同局，不能重新发牌 |
| 刷新原型 | sessionStorage支持同标签页恢复，不承诺跨设备持久化 |
| 终局 | 正常胡、黄庄、中止分开，真实分项与支付来自裁判 |
| 再来一局 | 回房重新准备，局号递增，不重复结算或自动发牌 |

黄庄无杠收入、查听或罚款；一炮多响分别标记赢家与同一放炮者。原型示例分数不当真实结果。超时、踢人、接管、托管、回收和房主转让待产品确认。

## 空态与异常

无手牌／副露／花／弃牌自然留白；尚未发牌保留四家身份并明确开始。数据未知用—，不把未知当0或黄庄。加载失败给重试与返回；军师失败不阻塞；响应过期明确拒绝且不重复提交。没有动作不出现按钮条。

## 原型边界与验收

App是本地流程演示，右侧模拟加入、准备、推进、胡／黄庄／多响是设计工具，不是正式产品按钮。case链接刷新重载示例；普通入口支持同标签恢复。样例场景不组成连续合法牌谱，也不证明真实联网或成熟棋力。

完整覆盖默认／选中／不可提交／空态／失败；开局、摸打、吃碰、各种杠、留花换花、听胡、过圈、互锁、终局、重连、离开和容量。用[Flow](flows/index.html)与[完整App](app/index.html)逐项检查。场景目录从 `shared/scenarios.js` 生成，不再维护一份手工Markdown清单。

四类验收分别进行：组件状态、完整流程、真实裁判合法性、联机恢复；不能互相替代。手机原型的方向与尺寸见上节，真实触摸、微信容器适配、倒计时与超时政策仍待验证。素材许可随素材保留，见[第三方说明](../src/simulation/webapp/THIRD_PARTY.md)。
